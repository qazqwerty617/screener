# Ускорение загрузки мультиграфиков

20 сентября 2026.

## Исправления

- Медленные ячейки через 450 мс пробуют прямой API своей биржи параллельно с
  серверным потоком. Первый успешный ответ отображается сразу. Раньше резервный
  путь ожидал сообщения pending, завершения потока или таймаута 12 секунд.
- Не более трёх прямых запросов одновременно на группу биржа/таймфрейм.
  Успех сервера, отмена ячейки или переключение страницы отменяют ненужные запросы.
  Ошибка прямого API, включая CORS, сохраняет возможность получить серверный ответ.
- На сервере попадания в кеш, включая полный кеш истории, идут первыми.
  Они больше не стоят за шестью незавершёнными обращениями к бирже.
- Ограничение частоты MEXC применяется к новым сетевым запросам; выдача кеша
  больше не задерживается интервалами между запросами.
- Первичные прямые запросы Bitget, Gate, MEXC, HTX и Hyperliquid ограничены
  300 свечами вместо 1 000–2 000. Более ранняя история загружается при прокрутке.
- Версия app.js: 2104.

## Измерение

`node .scratch/multichart-performance/benchmark.cjs`

Использован реальный код загрузчика до изменений (Git HEAD) и после изменений.
Задержки сети контролируются: медленный сервер 1 500 мс, прямой API 120 мс,
тёплый кеш 20 мс. Это воспроизводимый стенд, а не замер production.

| Сценарий | До: первый / все | После: первый / все |
|---|---:|---:|
| 9 графиков с разных бирж, медленный поток | 1 543 / 1 564 мс | 605 / 623 мс |
| 12 графиков одной биржи, медленный поток | 1 529 / 1 529 мс | 593 / 966 мс |
| 9 графиков с разных бирж, тёплый кеш | 45 / 45 мс | 45 / 45 мс |

Для тёплого кеша дополнительных запросов к биржам нет. При медленном сервере
ускорение достигается дополнительным ограниченным запросом для каждой ожидающей
ячейки. Фактическая скорость зависит от биржи, сети и доступности прямого API.

## Проверки

Два новых теста сначала воспроизвели ожидание кеша за холодными запросами и
отсутствие раннего резервного пути. После исправления проходят, в том числе:
отмена старых страниц, общий запрос для нескольких потребителей, лимит
параллельности, CORS-ошибка, отсутствие лишних запросов при быстром кеше,
корректная серверная агрегация 3d и ограничение размера первого ответа.

32 целевые проверки успешны. Полный набор: 682 / 682. `git diff --check` чист.

Изменения находятся в рабочей копии; на удалённый сервер не развёрнуты.
